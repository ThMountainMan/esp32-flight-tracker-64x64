✈ ESP32 Flight Tracker

Browser-based firmware installer — requires USB + Chrome or Edge

esp32-dev (standard ESP32 DevKit)

Flash the latest release firmware to a standard ESP32 DevKit board (WROOM/WROVER module, 4 MB flash). The installer writes the bootloader, partition table, boot_app0 helper, and application binary at the correct offsets. No credentials are included; see the note below about configuration.

⚠ Your browser does not support Web Serial. Use Google Chrome or Microsoft Edge (desktop).
Before flashing: plug in a USB data cable (not charge-only), open this page in Chrome or Edge, click the button, and select the correct serial port. On some boards you must hold the BOOT button while clicking "Connect". On Linux, add your user to the dialout group: sudo usermod -aG dialout $USER and re-log in.
Configuration happens after flashing — no extra steps needed. On first boot the device starts a temporary Wi-Fi access point called FlightTracker-Setup-<id>. Connect your phone or laptop to that network, open http://192.168.4.1/ in a browser, and enter your Wi-Fi credentials, location, and display settings. The device saves the configuration and reboots into normal operation automatically. See WEB_FLASHER.md for the full walkthrough.

Supported boards

Currently only the esp32-dev (standard ESP32 DevKit) target is published. The esp32-s3 environment uses a different bootloader offset (0x0000) and requires PSRAM configuration verification before a separate manifest can be safely published. Track progress in the repository issues.

Requirements & troubleshooting

• Browser: Google Chrome or Microsoft Edge (desktop).
• Cable: USB data cable — pure charge cables lack the data lines.
• Local only: the ESP32 must be plugged into your computer; GitHub-hosted runners have no USB access.
• BOOT mode: if the flash fails, hold the BOOT button on the ESP32 before clicking "Connect", then release after the port appears.
• Linux permissions: sudo usermod -aG dialout $USER, then re-log in.
• Private repository: if this repository is private, GitHub Releases and Pages may require authentication. Make the repository public or use a PAT / alternative distribution method before the public installer will work for end users.
